# StarUML diagrams: k3s job-search pipeline

Five StarUML 6 models for the laptop-hosted k3s pipeline, plus exports and the
generator that produced them. The source of truth for the content is
`docs/diagrams/facts.md` (live cluster evidence, 2026-10-11) and the Obsidian
architecture note.

## How the files were validated

Each `.mdj` is loaded by the real app to export, so a successful export is a
load test:

```
/Applications/StarUML.app/Contents/MacOS/StarUML image 01-uml-deployment.mdj -f svg -o export/01-uml-deployment.svg
```

The CLI subcommands are `ejs|image|html|pdf|exec`; `image` takes `-f png|jpeg|svg`
and `-o` (and `-s` to select a diagram). Then the SVG text is grepped for the
expected labels (node names, attribute rows, edge labels, note text). The
committed exports had the app's `UNREGISTERED` demo watermark stripped, as
plain `<text>` elements, and nothing else was changed. The `.mdj` files are
kept as the app-native source the exports come from.

## How the schema was learned

StarUML 6 has no view-bearing `.mdj` samples, so the schema was decoded from
the app bundle: `app.asar` -> `extensions/essential/uml/metamodel.json` and
`elements.js` (`UMLNodeView`, `UMLClassView`, `UMLNoteView`, `UMLDependencyView`
class definitions) plus the bundled `UMLMinimal.mdj` template. Empirical
findings (each confirmed by export-and-grep):

- View text is generated by the app from the model. Hand-written `subViews`,
  `nameCompartment` or `attributeCompartment` refs cause the app to drop the
  view entirely. Views therefore carry geometry only; the element carries the
  `name`, the `attributes`, or the note text.
- `UMLNoteView` never reads the model: multi-line note text belongs on the
  VIEW (`text`), not on the `UMLNote` element.
- An edge view needs distinct ids for its model element and its view; reusing
  one id suppresses the edge label.
- Edges are the one exception to the geometry-only rule: a relation view owns
  its three `EdgeLabelView` sub-views and the `nameLabel` / `stereotypeLabel`
  / `propertyLabel` refs; boxes never carry `subViews`.
- Class attribute rows are label views whose `text` lives on the row view, and
  the class element keeps attributes in its own `attributes` array.

Those findings are the complete set the generator relies on.

## Layout policy

Graphic text runs left to right, one label per line. Boxes are sized from
their longest line (about 6.3 px per character at Arial 12), so nothing wraps
or clips; each grid keeps at least one row of slack and box overlap is checked
at generation time. Notes carry the reading guide for each diagram.
